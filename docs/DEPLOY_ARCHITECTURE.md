```
│                              │ 读写分离                            │

```

### 3.2 数据面与控制面分离

```
 ┌──────────────────────────────────────────────┐
 │               Control Plane                   │
 │      (独立部署，不承载用户数据流量)             │
 │                                               │
 │  职责: 资源编排 / 调度 / 监控 / 备份 / 计费    │
 └──────────────┬───────────────────────────────┘
                │ 管理链路 (低频)
                │ gRPC / Agent / Ansible
                ▼
 ┌──────────────────────────────────────────────┐
 │               Data Plane                      │
 │      (承载用户读写流量，低延迟要求)             │
 │                                               │
 │  职责: 执行 KV 命令 / 复制 / 持久化            │
 └──────────────────────────────────────────────┘
```

**关键设计原则**：管控面故障不影响数据面正在运行的实例，用户读写不受影响。

## 4. 部署模式详细对比

### 4.1 模式 A：Docker Compose 单机（当前）

```
资源: 1 台机器
部署: docker compose up -d
扩缩: 手动改 compose
故障: 全挂
```

| 适用 | 不适用 |
|------|--------|
| 开发测试 | 生产环境 |
| CI/CD 集成测试 | 需要高可用 |
| 本地验证 | 流量超过单机容量 |

---

### 4.2 模式 B：VM 镜像直装（云缓存主流）

```
┌──────────────────────────────────────────────────────────┐
│                    镜像构建 (Packer / cloud-init)          │
│                                                          │
│   FROM ubuntu:22.04                                      │
│   ├── apt install 运行时依赖                               │
│   ├── COPY keydb-server → /usr/local/bin                  │
│   ├── COPY keydb.conf → /etc/keydb/                       │
│   ├── systemd unit: keydb-server.service                  │
│   ├── 内核调优: vm.overcommit_memory=1                    │
│   ├── 内核调优: net.core.somaxconn=65535                  │
│   ├── 关闭 THP (Transparent Huge Pages)                   │
│   └── 挂载 NVMe 本地盘 → /data/flash                      │
│                                                          │
│   产出: keydb-flash-vm.qcow2 / AMI / 云镜像                │
└──────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────┐
│                    多机部署                                │
│                                                          │
│   Host-1 (8C/32G/NVMe)     Host-2 (8C/32G/NVMe)          │
│   ┌──────────────────┐    ┌──────────────────┐           │
│   │ keydb-server      │    │ keydb-server      │           │
│   │ role: master      │◄───│ role: replica     │           │
│   │ --replicaof none  │    │ --replicaof Host-1 │          │
│   │ FLASH: /data/flash│    │ FLASH: /data/flash │          │
│   └──────────────────┘    └──────────────────┘           │
│                                                          │
│   Host-3 (8C/32G/NVMe)                                   │
│   ┌──────────────────┐                                   │
│   │ keydb-server      │                                   │
│   │ role: replica     │                                   │
│   │ --replicaof Host-1 │                                  │
│   │ FLASH: /data/flash│                                   │
│   └──────────────────┘                                   │
└──────────────────────────────────────────────────────────┘
```

| 对比维度 | Docker Compose | VM 镜像直装 |
|---------|:---:|:---:|
| 网络延迟 | 多一层 bridge | 裸网卡直连 |
| 磁盘延迟 | overlay2/volume | NVMe 裸盘 |
| 启动速度 | ~秒 | ~秒 (systemd) |
| 镜像分发 | Docker Registry | 云镜像市场 / AMI |
| 跨机部署 | 需额外改造 | 天然支持 |
| 内核调优 | 受限 (共享宿主机内核) | 完全可控 |
| 运维复杂度 | 低（单机） | 中（每台 VM 独立） |
| 阿里云 Redis 是否用 | 否 | ✅ 是 |

### 4.3 模式 C：K8s StatefulSet + Local PV

```
┌────────────────────────────────────────────────────────────┐
│                      K8s Cluster                            │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                  StatefulSet: keydb                    │   │
│  │                                                       │   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐   │   │
│  │  │ keydb-0     │  │ keydb-1     │  │ keydb-2     │   │   │
│  │  │ (Master)    │  │ (Replica)   │  │ (Replica)   │   │   │
│  │  │ PVC: nvme-0 │  │ PVC: nvme-1 │  │ PVC: nvme-2 │   │   │
│  │  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘   │   │
│  │         │                │                │           │   │
│  └─────────┼────────────────┼────────────────┼───────────┘   │
│            │                │                │               │
│  ┌─────────▼────────────────▼────────────────▼───────────┐   │
│  │              Headless Service: keydb-svc               │   │
│  │   DNS: keydb-0.keydb-svc, keydb-1.keydb-svc ...       │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              StorageClass: local-nvme                  │   │
│  │   provisioner: kubernetes.io/no-provisioner            │   │
│  │   volumeBindingMode: WaitForFirstConsumer             │   │
│  └──────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────┘
```

| 优势 | 劣势 |
|------|------|
| 声明式管理，自动调度 | 网络性能损耗 (CNI overlay) |
| 滚动更新、自动重启 | Local PV 绑定节点，Pod 不能漂移 |
| 生态完善（监控/日志/Ingress） | 运维复杂度高 |
| HPA 自动扩容 (无状态场景) | 有状态扩缩需 Operator 支持 |

### 5.2 扩容调度流程

```
用户请求: 扩容 (增加 Replica)
        │
        ▼
┌───────────────┐
│   API Server   │  接收请求 → 参数校验 → 写任务到元数据库
└───────┬───────┘
        │
        ▼
┌───────────────┐
│   Scheduler    │  定时扫描待处理任务
└───────┬───────┘
        │
        ▼
┌───────────────┐
│  选主机策略     │
│               │
│  ① 过滤:       │
│    - CPU/Mem/Disk 余量足够
│    - 不在同一物理机 (反亲和)   │
│    - 同地域 (低延迟)            │
│    - 节点健康                   │
│               │
│  ② 排序:       │
│    - 资源碎片最少优先            │
│    - 负载最低优先                │
│    - 成本最低 (按机型)           │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│  执行引擎      │
│               │
│  ① 从镜像仓库拉取 VM 镜像       │
│  ② 创建 VM / 容器               │
│  ③ 下发配置:                    │
│     storage-provider flash /data│
│     replicaof <master_ip> 6379  │
│  ④ 启动 keydb-server            │
│  ⑤ 等待复制同步完成              │
│  ⑥ 更新元数据库状态              │
└───────────────┘
```

### 5.3 故障自愈流程

```
  Monitor 检测到 Master 不可达
            │
            ▼
  ┌──────────────────┐
  │ 确认故障 (3次探测) │
  └────────┬─────────┘
           │ 确认故障
           ▼
  ┌──────────────────┐
  │  Failover 决策    │
  │                  │
  │  ① 选新 Master:   │
  │     复制 offset 最大的 Replica
  │                  │
  │  ② 执行切换:      │
  │     SLAVEOF NO ONE (新 Master)
  │     更新 VIP 指向新 Master
  │     其他 Replica → 指向新 Master
  │                  │
  │  ③ 补充 Replica:  │
  │     自动创建新节点补充到目标数量
  └──────────────────┘
```

## 6. 方案选型决策树

```
开始
  │
  ├── 只有 1 台机器？
  │   └── YES → Docker Compose (当前方案 ✅)
  │
  ├── 有多台机器，但没有 K8s？
  │   └── YES → VM 镜像 + systemd + 手动 replicaof
  │              (最接近云缓存厂商做法)
  │
  ├── 已有 K8s 集群？
  │   └── YES → StatefulSet + Local PV + Headless Service
  │
  ├── 需要自动扩缩容 + 多租户？
  │   └── YES → 管控面 + 调度引擎 (见第5节)
  │
  └── 直接用云厂商托管服务 (阿里云 Redis / AWS ElastiCache)
      └── YES → 不需要自己运维 🤷
```

## 7. 各模式性能对比

| 指标 | Docker Compose | VM 镜像 | K8s Local PV | 云托管服务 |
|------|:---:|:---:|:---:|:---:|
| 内存读写延迟 | ~ns | ~ns | ~ns | ~ns |
| FLASH 读取 | ~100μs | ~50μs | ~100μs | ~50μs |
| 网络 RTT | ~0.1ms | ~0.1ms | ~0.3ms (CNI) | ~0.1ms (VPC) |
| CPU 损耗 | ~2% (容器) | ~0% | ~5% (容器+CNI) | ~0% |
| 单节点最大连接 | ~10k | ~100k | ~10k | 按规格 |
| 故障恢复时间 | 手动 | 手动 / 分钟级 | 自动 / 分钟级 | 自动 / 秒级 |
| 运维投入 | 低 | 中 | 高 | 零 |
